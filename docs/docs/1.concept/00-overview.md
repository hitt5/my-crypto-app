## ひとことで言うと

「AIに相場を当てさせるアプリ」ではなく、**オンチェーンに散在する資産形成機会（Airdrop / Yield / リバランス等）を発見し、危険を避け、面倒な実行を積み重ねる AI 資産形成 OS**。資産（秘密鍵）はユーザーが持ち、Agent は期限付き・用途限定の権限と決定論的なポリシーエンジンに拘束される — **Non-custodial, policy-custodied autonomy**。

## プロジェクトタイプ（ルート README §1.1 から選ぶ）

| 項目 | 値 |
|---|---|
| タイプ | **A 戦略・仮説検証型 + E モニタリング型** の組み合わせ |
| 選定理由 | Opportunity（エアドロップ期待・イールド機会等）は「前提条件つき仮説」として管理し外部変化で検証する（A）。同時に、ポートフォリオ目標配分・Policy（投資憲法）という正本と、オンチェーン実態（残高・Approval・プロトコル健全性）との差分を常時監視し、DRIFTED を検知して是正する（E）。価格予測は主役にしない |
| データモデルの起点 | A=前提条件つき Opportunity 仮説 ＋ 外部変化（市場・オンチェーン・プロトコル情報） / E=正本（Policy・目標配分）＋ 実態観測（ウォレット・ポジション・リスクシグナル） |

## 課題（Before）→ 変わること（After）

| Before | After |
|---|---|
| 数百プロトコルの巡回・エアドロップ期限管理・Claim・Approval 解除を人間が継続できず、機会を取りこぼす | Agent が 24 時間クロール・期限管理・Claim 検知を行い、オペレーショナルαを取りこぼさない |
| APY 等の表面利回りだけで判断し、コントラクト障害・デペッグ・IL 等のリスク調整後はマイナスの投資をしてしまう | 期待純収益（基礎金利＋報酬−ガス−スリッページ−ヘッジ費用−期待損失）で機械的に評価する |
| 従来の自動売買は API キー丸渡しのブラックボックス。売買回転が増えて手数料・ノイズで負ける（FX 自動売買と同じ構造） | 権限は期限付き・用途限定。デフォルトは「何もしない」。取引しない理由を先に探し、回転数に上限を設ける |
| なぜ投資したか・どの情報源が正しかったかが残らず、失敗から学べない | 全判断を Evidence Ledger に記録し、Agent 介入による増分利益を「何もしない場合」と比較測定する |
| 危険（デペッグ・脆弱性・Admin key 変更）への退避が人間の気づき頼み | Guardian Agent が異常検知 → 新規取引停止 → 権限停止 → 退避案 → 人間へ緊急承認まで自動化 |

## このテーマが答える問い（3つ前後に絞る）

> 1. **どのオンチェーン機会が本当にプラスか** — Airdrop / Yield / リバランス等の機会は、ガス・スリッページ・リスク（期待損失）調整後にプラスの期待純収益を持つか。どの情報源の信頼度に基づくか。
> 2. **Agent の介入は増分利益を生んでいるか** — 「BTC を持っていただけ」「ステーブルで保持しただけ」「何もしなかった場合」と比較して、Agent 介入の増分利益（手数料・ガス・税務込み）はプラスか。
> 3. **権限とポリシーは常に守られているか** — 秘密鍵非保持・金額上限・Allowlist・回転数上限・損失限度・権限失効という投資憲法が、全実行で機械的に検査され、逸脱ゼロを証明できるか。
