# 01 — 課題認識（Problem）

> **テーマ**: dodo Crypto Wealth OS / **theme_id**: `crypto-wealth-os` / **profile**: `crypto` / **作成**: 2026-08-22
> **標準**: [`README.md`（コンセプト設計標準）](README.md) の品質バーに従う。
> **上位原理**: [`00-overview.md`](00-overview.md) の大原則（不可逆損失の回避 × 介入可能性の最大化）。本書の課題はすべてこの原理の欠如から導出される。

## 現状の問題

### 0. 価値原理の欠如 — 損失最小化でも期待収益最大化でも破綻する（根本課題）

既存の自動運用・個人運用には、**生存と選択肢を統べる価値原理が存在しない**。

- **損失だけを最小化**すると、最適解は常に「何もしない・現金で持つ」に退化する。機会も知識も蓄積されず、インフレと機会損失で緩やかに敗北する
- **期待収益だけを最大化**すると、レバレッジを上げ、Tail Risk を無視し、いつか一撃で破綻する。破綻した資本は次の機会を取れない（Survival Premium の喪失）
- 両者の間を「なんとなくのリスク許容度」で運用すると、判断が状況依存になり、機械実行も検証もできない

必要なのは単純な損失最小化ではなく、**生存制約下での幾何平均成長と Optionality 最大化**（`max E[Δlog W + αΔΩ + βIG] s.t. P(ruin) < ε`）という単一の定式化である。これがなければ、以下のすべての個別課題への対処は場当たりになる。

### 1. リスクが「価格変動」として誤定義されている

個人の運用もほとんどのツールも、リスクをボラティリティ（価格変動幅）として管理する。しかし本当のリスクは**将来の意思決定能力を失うこと**、すなわち不可逆性である。

- レバレッジによる強制清算・資金ロック・Bridge 停止・秘密鍵流出
- 単一 Protocol への集中・同じ担保への見えない相関（見かけ上の分散）
- 税務負債・流動性枯渇・モデルが理解できない Contract への投入

これらの不可逆リスクは管理されず、逆に「価格変動は大きいが、無借金・損失上限明確・Upside 非対称」という良い機会がボラティリティを理由に見送られる。**ボラティリティではなく不可逆性を最小化する**枠組みが個人には存在しない。

### 2. 「誰が・いつ・なぜ動かざるを得ないか」を見ていない（Constraint Alpha の不在）

Agentic 時代に情報の非対称性と実行速度の差は縮小する。しかし**制約の非対称性**は最後まで消えない。全員が同じ情報を同じ瞬間に知っても — 清算される Agent、月末に売らねばならないファンド、Governance 承認が必要な Treasury、税務上売れない投資家、在庫解消を迫られる Market Maker — は同じ行動を取れない。

| 分析 | 見ているもの | 役割 |
|---|---|---|
| ファンダメンタル | 価値の因果的 Anchor | どこへ収束し得るか |
| テクニカル | 市場参加者の行動結果 | 現在どちらへ動いているか |
| **Positioning / Constraints** | レバレッジ・期限・義務・流動性 | **誰がいつ強制的に動くか** |

個人はこの第三軸（清算・Unlock・Incentive 終了・償還期限・Governance 変更・Collateral 不足の構造的予測）を継続観測できず、市場の本質的な Alpha が「何が正しいか」から「誰が動かざるを得ないか」へ移っていることに対応できない。

#### 補足: これは本当に観測できるのか（観測可能性の等級）

「制約の観測」は一様ではない。**完全観測は不可能だが、Crypto は制約が Contract に書かれているため、TradFi より構造的に観測可能性が高い**。これがこのテーマが crypto プロファイルで成立する前提であり、対象は 3 等級に分かれる:

| 等級 | 対象例 | 観測方法 | WM-3 上の扱い |
|---|---|---|---|
| 🟢 **direct（直接観測 = 高精度）** | 清算水準（Lending Protocol の全ポジション・Health Factor はオンチェーン公開 — 「価格が X% 下がると $Y 清算」のヒートマップを構築可能）、Token Unlock（Vesting Contract に deploy 時点で確定）、Incentive 終了（Emission パラメータ・終了ブロックは Contract 記載）、Governance 日程（提案・投票・Timelock は公開・猶予時間も確定値）、Collateral 不足の予兆（担保比率・利用率はリアルタイム） | RPC / インデクサ / subgraph による一次観測 | **Fact** |
| 🟡 **proxy（プロキシ経由の推定）** | Perp ポジショニング（Funding Rate・OI・Long/Short 比率から推定 — CEX 内部の個別ポジションは不可視）、Market Maker 在庫（既知アドレスのラベリング依存）、同一モデル混雑（同一 Stop 価格帯・TVL 集中・行動の同質性から逆算 — §4 参照） | 集計値・ラベリング・クラスタリングからの推定 | **Belief** |
| 🔴 **structural-prior（構造的事前知識のみ）** | 月末に売らねばならないファンド（TradFi の償還・リバランス義務は非公開 — 季節性ヒューリスティクスが限界）、税務上売れない投資家（完全に非公開 — 年末 tax-loss selling 等の集計統計のみ） | 公開されない。構造的な傾向としてのみ保持 | **Hypothesis** |

課題として重要なのは、🟢 の直接観測可能な部分（清算マップ・Unlock カレンダーだけでも実用的な Constraint Alpha の一部）ですら個人は継続観測していないという点である。本文の例示に含まれる 🔴 は「制約の非対称性が消えない」ことの説明であり、直接の観測対象ではない。ConstraintNode（[`../2.sdt-design/02-data-model.md`](../2.sdt-design/02-data-model.md)）はこの等級を属性として持ち、Fact / Belief / Hypothesis を混ぜない（WM-3）。

### 3. 正解率を追い、Payoff 構造（Convexity）を見ない

「上がるか下がるか」の的中率を上げようとする運用は、10回中7回当てても一度の損失で全てを失う。逆に損失1・利益10・成功確率20%の機会は期待値が正になり得るのに、正解率の低さを理由に見送られる。必要なのは単一予測値ではなく、**各未来の確率分布 × 損益分布 × 不可逆性**の推定だが、これを人間が継続的に行うことは実務上不可能。

### 4. Reflexivity（同一モデルの混雑）を扱えない

Agent の予測が行動になり、その行動が市場を変える。皆が同じモデルで同じ Protocol へ移動し、同じ価格で Stop を置き、同じ Risk-off をし、同じ担保を売却すれば、**モデル自身が危機を作る**。既存ツールは「他の Agent が何を予測しているか」「同じ Policy を持つ参加者がどれだけ混雑しているか」を観測対象に含めておらず、Agentic 化が進むほどこの盲点は致命的になる。

### 5. オペレーショナルαの取りこぼし（継続不能な手作業）

オンチェーンの資産形成には「地味だが大量にある作業」が収益源（オペレーショナルα・インセンティブα）として存在するが、人間には継続できない。

- 毎日数百のプロトコル・ガバナンスフォーラム・GitHub 更新の巡回
- 金利・報酬・TVL・流動性の変化検知
- エアドロップの Eligibility 条件と期限の管理、Claim 可能の検知
- 不要な Token Approval の解除（放置は不可逆リスク＝鍵・権限の露出）
- 資産配分の乖離検知とリバランス
- 税務用の取得価格・取引理由の記録

これは大原則の観点では **Ω（介入可能性）の維持コスト**であり、放置は選択肢集合の縮小そのもの。

### 6. 既存自動売買の構造的欠陥（FX 自動売買の再来）

- 「戦略を選ぶ → API キーを渡す → ブラックボックスが売買する」という丸投げ構造。権限の可視化も判断根拠の追跡もできない。**鍵・権限の丸渡しは最大の不可逆リスク**
- AI に価格予測をさせて売買回数を増やすと、手数料・スリッページ・ノイズ取引が増えて負ける（価格予測αは再現性が最も低い）
- Agent は疲れないが「市場ノイズに反応し続ける」という別の弱点を持つ — 回転数の上限と No-action との Counterfactual 比較がなければ損耗する

### 7. 危険からの退避が人間頼み

ステーブルコインのデペッグ、Oracle 異常、TVL 急減、Admin key 変更、Contract upgrade、Governance 攻撃、Bridge 停止、フロントエンド改ざん — これらは価格変動ではなく**不可逆性イベント**であり、検知と退避が人間の気づきに依存している。**不可逆損失を一度回避する価値は、細かいトレードで数年間稼ぐ利益より大きい**（Survival Premium）のに、最も自動化されていない。

### 8. 投資判断の知（情報利得 IG）が蓄積されない

どんな Opportunity があったか、どの情報源が正しかったか、なぜ投資したか、どのリスクを見落としたか、何もしない方がよかったか — これらが記録されず、失敗から学習できない。大原則における **IG（情報利得）項がゼロのまま**であり、「ウォレット全体で増えた」だけでは介入の増分利益もモデルの校正度も測れない。

## なぜ今やるのか

- **Agentic 化による非対称性の移動**: 情報差・速度差の Alpha は Agent の普及で消えていく。残るのは制約の非対称性（Constraint Alpha）と Payoff 設計（Convexity）であり、これらは World Model + Constraint Graph を構造的に持つ者だけが取れる。早期に構築するほど IG の複利が効く
- **Smart Account / Session Key の成熟**: Safe の Module/Guard、Intent 型執行（CoW Protocol 等）により、「秘密鍵を渡さず、期限付き・用途限定の権限だけを委任する」＝不可逆リスクを構造的に切り離すアーキテクチャが実装可能になった
- **Agent 基盤の成熟**: dodoAI の SDT / Multi-Agent / HIL / Evidence により、「暴走しない・説明できる・権限を奪えない」AI を統治構造ごと構築できる
- **規制の移行期（2026）**: 金融庁 WG で暗号資産を金商法上の金融商品として扱う方向が示され、制度移行期にある。「実行前承認を標準」「ユーザー定義ルールの機械的実行」「自己勘定支援」という設計を最初から選ぶことで、規制適合と差別化を両立できる
- **競争軸の選択**: 運用成績（予測精度）の競争はクオンツ・取引所・ファンドとの正面衝突。「生存原理・不可逆性管理・Constraint Graph・確度校正」という別の防衛線は今なら先に築ける

## 放置した場合のリスク

| リスク | 影響 | 大原則上の意味 |
|---|---|---|
| 価値原理の不在 | 不作為への退化 or レバレッジ破綻の二極 | 目的関数が定義されないまま最適化が走る |
| 不可逆リスクの未管理 | 清算・鍵流出・資金ロックによる回復不能な損失 | P(ruin) が管理されない — 最悪の失敗 |
| 制約非対称性の無視 | 他者の強制行動（清算連鎖・Unlock 売り）に轢かれる側に回る | Constraint Alpha を取られる側になる |
| 同一モデル混雑の無視 | Risk-off の同時発生・退避経路の混雑で退避不能 | Reflexivity がモデル自身の危機を作る |
| 手動運用の継続不能 | エアドロップ・Claim・金利機会の恒常的取りこぼし。Approval 放置による露出 | Ω の維持コストを払えず選択肢が縮小 |
| 既存ボット型（API キー丸渡し）の採用 | 権限の不可視化・ブラックボックス化。高回転売買による手数料負け | 最大の不可逆リスクを自ら導入 |
| 判断記録の不在 | 同じ失敗の反復。戦略の良否を「相場のせい」と切り分けられない | IG = 0。学習しないシステム |
| 規制動向の無視 | 助言・媒介・運用該当による事業リスク | 規制は Constraint Graph の自分側のノード |
